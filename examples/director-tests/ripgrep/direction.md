# ripgrep · an ignored-file storm becomes matching lines

**Held-out GitHub test.** This project was not among the four films used to develop the content-directed method. The source is ripgrep's commit-pinned README. The official [README](https://github.com/BurntSushi/ripgrep) describes recursive regex search, default ignore rules, skipped hidden/binary files, and the `rg -tpy foo` type filter. We show no benchmark because the README's comparisons depend on a specific corpus and hardware.

**Input → mechanism → output.** A current directory full of file surfaces → recursive traversal filters ignored/hidden/binary material and scans eligible lines for a regex pattern → matching lines are highlighted. This is a visual metaphor for a search operation, not an actual run or measured file count.

**Direction choice.** A first-person storm of file slates was chosen over a terminal-only waterfall. The latter is accurate but gives the search no spatial consequence. Here the camera moves into an immense file field; gray ignored slates peel away, eligible slates pass through a bright regex plane, and a sparse set of golden line fragments emerges. The action starts in the first second. The center undergoes a structural change from mass to filtered lines, while a narrow perimeter carries the source-backed command and filtering facts.

Sound marks the filter, scan, and result beats.

**Evidence boundary.** No visible file names, match text, counts, rankings, or timings are claimed as real. The abstract slates and highlights are labeled as an illustrative search field.
